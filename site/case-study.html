Quickstart Rules Comparison Case study Papers

Written 2026-11-13

Expectrail, the first adopter, is one author's own project.

Osita Sean Keluo-Udeke maintains Expectrail with Timothy Itodo. This page is no evidence that a team with no tie to OBAAF finds it useful. Results from outside teams are still to come, and none has been reported.

The source is the case study. The numbers below are that document's.

What that document says worked

  • Expectrail declared its agent jobs, and the checker then asked what each could reach. Without the declaration file, the document says OBAAF recognises 2 of 19 as agent jobs.
  • Jobs that use a model key name one environment, main-only, limited to main.
  • The gate on main, from Expectrail's #223 at 17:36 UTC on 2026-11-10, pinned OBAAF to d014b63. It caught an agent job that reached main without baseline entries. The document says main went red about three hours later. Nothing was undone: the findings were accepted.

What it says did not

  • Each finding the gate raised was answered by accepting it. The baseline went from 32 to 38 entries in 21 hours. Every entry was OBAAF-GHA-005 or OBAAF-GHA-020. The document says OBAAF itself offered no fix for either at the pin Expectrail runs. It also says that pin's checker clears OBAAF-GHA-020 for a blocking Harden-Runner step, and that Expectrail has not adopted one.
  • The six incidents the work began from were, as reported, in GitHub's settings, which that pin did not read. The list of six is the account the case study started from, and the document says where the public record supports each one.
  • Nothing OBAAF ran restricted a job at run time. It reported.

What is newer than that page

The case study says an egress control exists and the checker does not credit it yet. That sentence is the page as written on 2026-11-13. The development checker is written to clear OBAAF-GHA-020 for GitHub's native egress firewall in enforce mode. OBAAF's own action stays "cannot tell" until a released commit is listed, and none is listed. OBAAF-GHA-005 still cannot be cleared. The firewall clearing is not in release 0.3.0. Release 0.3.0 does drop OBAAF-GHA-020 for an unconditional Harden-Runner step with egress-policy: block, which is a different, narrower test. The rules page records the 2026-11-14 runs.

Expectrail, as the case study records it, still runs the OBAAF of 2026-11-10, commit d014b63. The later work does not apply to it until that pin moves.

Phase A is dated 2026-10-30 in that document. The gate command it quotes is in the block below.

obaaf check . --baseline .github/obaaf-baseline.json --fail-on low --no-fixes

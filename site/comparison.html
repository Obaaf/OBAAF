Where OBAAF does not try to be the only tool.

This page is a short reading of the landscape at a583a7b. It is not a new comparison. The positioning section was written on 2026-11-11. Measurements of Checkov, Semgrep and ci-agent-audit were added on 2026-11-13. The positions are proposals until the maintainers accept them.

OBAAF is a small open-source project with one adopter, and that adopter is its author's own. Asking what an agent job in CI can reach is not OBAAF's alone. ci-agent-audit does. Wiz and Aikido say their products detect misconfigured agents in CI. Neither was tested for that landscape.

On 2026-11-13 the landscape's own H2 runs recorded that ci-agent-audit's AIA005 and AIA006 overlapped token-permission and egress findings on two agent fixtures, and that AIA001 identified prompt input OBAAF did not report. This page does not repeat every cell of those runs.

The aim, and what is true now

The landscape's position, as a thing being built towards, is: for jobs that run an AI agent or publish a release, say what each job can reach, check that a claimed control is real in the workflow file, in the repository's settings, and while the job runs, and show the evidence. For everything else, point at the tool that already does it.

One sentence in that section still says that today OBAAF reads files only, reads no settings, and enforces nothing while a job runs. The rows under it are later. On this checkout, not in release 0.3.0: obaaf audit reads repository settings it can see, and an optional egress action exists. OBAAF-GHA-020 can be cleared when the job runs on ubuntu-24.04-firewall and .github/egress-firewall.yaml sets mode: enforce, with a token that can read the file. OBAAF's own action stays "cannot tell" until a released commit is listed, and none is listed. A model key behind AWF's API proxy does not clear OBAAF-GHA-005. OBAAF ships no inference proxy. Release 0.3.0 is the file check.

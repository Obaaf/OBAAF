Try release 0.3.0

Install it, then check one file.

Python 3.10 or later. Installation downloads packages. The check reads a file on the machine and does not edit it. No action is run.

python -m pip install obaaf==0.3.0
obaaf --version
obaaf check unpinned.yml --fail-on low
obaaf check pinned.yml --fail-on low

Checked on 2026-11-14 at 04:24 UTC with obaaf 0.3.0 from PyPI. obaaf --version printed obaaf 0.3.0. The first command exited 1. The second exited 0. The finding is low. A medium threshold would not fail it. The same two files, checked again the same day with obaaf 0.3.0 and with the development version, exited 1 and then 0.

The finding

unpinned.yml
     9  LOW    OBAAF-GHA-008  Action or container not pinned to a full digest  [job build]
        Action 'actions/checkout@v6.0.0' is pinned to 'v6.0.0', not a full commit SHA.
        Requirement: G2.1, R6
        Fix: Pin the reference to a full 40-character commit SHA, or an image to its sha256 digest, and keep the version in a comment (for example `uses: actions/checkout@<sha> # v7.0.1`). Let Dependabot propose updates to the pin.

1 workflow file(s) checked.
Authority findings: 0 high, 0 medium, 0 low.
Hygiene findings: 0 high, 0 medium, 1 low.

The pinned file printed no findings. Pinning selects a revision. It does not prove that revision is safe. The checker's example comment says v7.0.1. That is its example, not this file's version. The commit in the pinned file is the one the actions/checkout repository tags v6.0.0.

Each file is one job: on: push, top-level contents: read, persist-credentials: false, and one action. The finding was on line 9.

A gate is a repository setting

The exit status does not configure a merge gate. Checking a file on your machine runs no workflow and blocks no merge. To make a failing check stop a merge, run the check in a workflow and require that status check in the repository's branch rules; that is a setting, not something OBAAF changes.

There is no obaaf init in release 0.3.0. Companion scanners are named on the comparison page. Setting them up is separate work.

The development version's report of the same two files adds lines release 0.3.0 does not print, including "Accepted risk: none" and a count of other findings. Those lines are not part of release 0.3.0. Release 0.3.0 already ignores a finding when an ignore entry has a rule, a path, a reason, and an until date that has not passed. Requiring an owner, and refusing a reason the checker judges too short, are not in that release.

An older hosted demonstration, using OBAAF 0.1, rated an unpinned action medium. From 0.2 its severity depends on the job. It is low, as here, when the job declares its permissions with no write scope, has no id-token permission, no secrets and no privileged trigger such as pull_request_target. It is medium on a job without those limits, including one with no permissions: block, and high on a job OBAAF treats as an agent job, a release job, or the job that applies an agent's approved change.

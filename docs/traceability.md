# Traceability: requirements to implementation and tests

The specification's roadmap figure plans specifications, templates, the checker, the verifier and tests for FR1–FR12 in version 0.1. Each functional requirement below has an offline test module that runs in CI (`python -m unittest discover -s tests`), and, where only a real GitHub repository can show the behavior, a [live acceptance test](live-acceptance-tests.md). None of the live tests has been run yet. Passing the offline tests is not production validation.

The status column says how far version 0.1 meets each acceptance criterion. "Met offline" means the offline tests show it; "Platform behavior unconfirmed" means the templates are written to get it from GitHub, but only the live test can show that GitHub behaves that way.

## Non-functional requirements

| ID | Requirement | Status in version 0.1 |
| --- | --- | --- |
| NFR1 | Free and open (CC BY 4.0, Apache 2.0) | Intended; public access does not grant a reuse license ([LICENSING.md](../LICENSING.md)) |
| NFR2 | Usable without security staff; kappa ≥ 0.61 | Plain-language items with evidence; agreement is measured in the pilot |
| NFR3 | Tiers 1 and 2 need no new tools | Not met for private repositories on every plan. Tier 1 needs no new tools, except that protecting release branches (item 1.6) needs a paid plan for a private repository. Tier 2 uses the free templates and tools, but on private repositories the agent and release lanes need GitHub Enterprise Cloud for artifact attestations and environment reviewers ([plan limits](github-settings.md#plan-limits)) |
| NFR4 | Release build time rises by no more than 5% | Hypothesis; measured in the pilot |
| NFR5 | Private by default, no telemetry | No telemetry: no command reports anything to OBAAF. In Sigstore mode, `obaaf verify release` and `obaaf verify agent-run` call the GitHub CLI, which sends artifact digests to GitHub to fetch and check attestations. The form's content security policy forbids network requests (tested in FR2) |
| NFR6 | Vendor-neutral requirements | The profile's requirements and items name no CI product; G6.1 cites Steam's guidance as Paper 2 does. The checker rules and detection patterns are specific to each CI platform they read: GitHub Actions workflows, and Jenkinsfiles as an advisory auditor (OBAAF-JEN rules; [Jenkins](jenkins.md)). The templates target GitHub Actions (D-014) |
| NFR7 | Stable IDs, changelog, decisions log, semantic versions | [CHANGELOG.md](../CHANGELOG.md), [DECISIONS.md](../DECISIONS.md); generated documents checked in CI |
| NFR8 | Mappings updated within 90 days of new SSDF or SLSA releases | Mappings in `frameworks.yaml`; SSDF 1.2 is still a draft |
| NFR9 | No confidential material | Built from public sources; every text file is tested for employer names (test_docs.py) |
